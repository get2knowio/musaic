## What the automated tests cover

Against a scratch home and a scratch temporary root, never a real Claude directory:

- the readiness report in every state (Claude Desktop absent, Linux, own entry, foreign entry,
  unreadable file, program missing, unstable location, ready) and the extension folder (detected,
  not detected, unknown);
- the command shown equals the command written, for both bundle shapes, with a program location
  holding spaces, quotes and non-ASCII characters, and `--config-dir` only for a non-default
  directory;
- the manifest's required fields, no `user_config` and no `env`, and the manifest's name and
  author tied to the extension folder's name;
- no generated byte holds a secret of the test fixture; nothing is written outside the temporary
  root; the file and its folder are private and removed on a failed open, after 60 minutes and at
  start;
- the skill archive: stable bytes and every file's digest equal to `skill.lock.json`;
- the desktop request's guards, the hook receiving exactly the generated file, and the answer
  naming no path.

Not covered by any automated test: Claude Desktop itself.

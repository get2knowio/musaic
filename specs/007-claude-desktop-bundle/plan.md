# Implementation Plan: One-click connection to Claude Desktop

**Branch**: `007-claude-desktop-bundle` | **Date**: 2026-11-24 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `specs/007-claude-desktop-bundle/spec.md`

## Summary

Add two actions to the Assistants section of Settings. **Connect Claude Desktop** shows a readiness report, then (inside the desktop shell only) has the application write an MCP bundle to a private temporary directory and opens it with the shell's opener, so Claude Desktop shows its own install dialog. **Save the Musaic skill for Claude** downloads a deterministic zip of the embedded skill. The bundle has two shapes, chosen per platform by one constant backed by recorded evidence: "installed program" (the command is the app's own `musaic-cli`) and "self-contained" (the bundle carries a copy). The command-line program reports its version when it connects, so the Assistants view can show one that is older than the app. The rule for where Claude Desktop's configuration file is, and for whose entry is in it, moves to one shared place used by both the CLI and the desktop.

## Technical Context

**Language/Version**: Rust 1.99.1 (edition 2024, `unsafe` forbidden); TypeScript / React
**Primary Dependencies**: existing (axum, tauri 2 with `tauri-plugin-opener`, TanStack Query). Added to `musaic-app`: `zip` (deflate only, default features off, pinned exactly) and `tempfile` promoted from a dev dependency (already in `Cargo.lock`). `semver` only if it is already in `Cargo.lock`; otherwise a small comparison of the workspace's own version form (research D9).
**Storage**: none. No schema change (schema stays v24). The reported CLI version is kept in memory with the live session facts.
**Testing**: `cargo test --workspace`, vitest; every test uses a scratch home and a scratch temporary root through an injected environment; no test touches a real Claude directory
**Target Platform**: macOS and Windows get the bundle; Linux gets the configuration-file route only
**Project Type**: desktop app (Rust workspace + web UI)
**Constraints**: no new listener; no secret in any generated byte; nothing from the page, a tool or a setting shapes the bundle; the CLI still links no database crate; `ops/agent.rs` stays free of `serde_json`
**Scale/Scope**: about 5 crates, one new app module, one shared module, one dialog component

## Constitution Check

*GATE: passed before research; re-checked after design.*

- **I. The library is the user's.** Pass. Nothing touches the library or its files. Nothing is written into the configuration directory.
- **II. Local-first, secure by default.** Pass. No listener, no change to the bind, launch gate, Host/Origin check, CSP or navigation lock. The bundle is built from the app's own resolved program location and fixed arguments; it declares no `user_config` and no `env`. The hand-off route is a shell request behind the launch cookie that takes no input. Claude's configuration is only read. No agent program is started: the operating system is asked to open one file.
- **III. One operations surface, events for fan-out.** Pass. Three operations in the existing `agent` group (`claude_desktop_status`, `claude_desktop_bundle`, `skill_archive`), two `/api` routes with inventory rows, and one shell request that calls one operation. No mutation of application state happens, so no new event; the version report reuses `AgentStateChanged(hosts)`.
- **IV. Derive from current state.** Pass. Readiness is derived on every request from the filesystem; nothing about Claude is cached or stored.
- **V. Test-backed, deterministic.** Pass. Manifest and zip bytes are deterministic (fixed timestamps, fixed order); the secret scan, the shown-equals-written check and the digest check are tests. What needs a real Claude Desktop is listed as evidence the owner records, with untested cells marked.
- **VI. Plain, accessible interface.** Pass. One dialog with the report, the exact command, and one confirm button; each unavailable state has its own sentence; the "not available yet" list has no controls.

No violation to justify.

## Design decisions (detail in [research.md](research.md))

1. **Two shapes behind one constant** (D1). `BundleShape::{Installed, SelfContained}`; `shape_for(platform)` in the generator returns `Installed` for macOS and Windows until evidence says otherwise. Both are implemented and tested; flipping a platform is a one-line change plus a doc line.
2. **The generator lives in `musaic-app`** (D2), module `agent/claude_desktop.rs`, behind an injected `HostEnv` (home, platform, executable path, temporary root, config dir and whether it is the default). The app builder gets a test-only override.
3. **Shared host rules in `musaic-commands`** (D3), module `claude_desktop.rs`: the configuration file location per platform and `entry_owner(text) -> Absent | Ours | Foreign | Unreadable` (today's `is_ours` rule). Pure functions over strings and paths; callers do the reading. `musaic-cli/src/setup.rs` uses them instead of its own copies.
4. **Program location** (D4): the sibling of the running executable, as `connect_hint` does today, factored into one function that also verifies it (a regular file, canonical path) and refuses a location that will not last (`/Volumes/`, `/.mount_`, an App Translocation path, anything under the temporary directory, unless the environment is a test's). `connect_hint` uses the same function.
5. **Hand-off through a shell request** (D5): `POST /__musaic/connect/claude-desktop` in the desktop gate, beside the dialog and reveal requests: launch cookie, exact Host, same Origin, POST, empty body. The gate calls `ops().agent().claude_desktop_bundle()` and passes the returned path to a new `Hooks::open_bundle`, which `TauriHooks` implements with the opener plugin's open-path call. The page marker gains `connectClaude`. The standalone server has no such route.
6. **Temporary files** (D6): `<temp>/musaic-connect-<random>/Musaic.mcpb`, directory private to the user. Removed on a failed open, by the app's periodic tick once older than 60 minutes, and at startup. Only directories with that prefix that hold nothing but that file name are removed.
7. **One hand-off at a time** (D7): an in-flight flag on the operation; a second call while one is being prepared answers Conflict.
8. **Skill archive as a download** (D8): `GET /api/agent/skill-archive`, the bytes of `musaic_commands::skill::bundle()` under `musaic-work-delegation/`, file name `musaic-work-delegation-<version>.zip`, saved by the same download handling as the database backup.
9. **CLI version** (D9): optional `cliVersion` on the session observation; kept in an in-memory map by pairing beside the live session facts, cleared on revoke; `diagnostics` returns `cliVersion`, `appVersion` and `cliOlder`. The CLI compares the descriptor's `app_version` with its own in `doctor` and at `mcp` start (stderr only).
10. **Status is fetched when the dialog opens** (D10): it depends on files outside Musaic that no event reports, so its query is the one place here with a stale time other than `Infinity`, with a comment saying why.
11. **No agent tool, no CLI subcommand** for the hand-off (FR-004); the tool catalog and the skill bytes do not change, so no skill version bump.

## Slices

Each slice leaves the workspace green (ciLocal and `catalog --check`).

### Slice 1 — Shared host rules and the CLI's words

`musaic-commands/src/claude_desktop.rs` (paths, `entry_owner`), used by `musaic-cli/src/setup.rs`. `uninstall --host claude-desktop` with no owned entry says where an extension is removed (FR-015). `setup --host claude-desktop` warns about two servers (FR-016). `doctor` gains one Claude Desktop line (entry state, and that extensions are managed in Claude) and an app-version comparison (FR-026). `cliVersion` added to the observation wire type and sent by the CLI.

Tests: unit tests for paths per platform and for each owner state (including invalid JSON and a non-object `mcpServers`); `musaic-cli/tests/setup.rs` unchanged behaviour plus the new messages; `no_db_owner.rs` still passes; `catalog --check` clean (no tool or skill change).

### Slice 2 — The application: status, bundle, archive

`musaic-app/src/agent/claude_desktop.rs`: `HostEnv`, detection, `cli_location`, `Command` (program + args, the single source for display and manifest), manifest, zip writing, temporary directory, cleanup; `ops/agent.rs`: the three operations with typed results; `agent/hosts.rs`: the in-memory CLI version; `musaic-api`: two routes, renderers, `EXTRA_ROUTES`, rows in `docs/operations.md`.

Tests (`musaic-app/tests/ops_agent_claude.rs`, `musaic-api/tests/claude_desktop_http.rs`): each readiness state against a scratch home; manifest validates against the checked-in copy of the 0.3 schema's required fields; shown command equals manifest command; both shapes; a path with spaces, quotes and non-ASCII; no secret in any byte (fixture with a pairing in the memory store); nothing written outside the temporary root (directory snapshot before and after); in-flight Conflict; cleanup rules; archive digests equal `skill.lock.json`; archive bytes stable across two calls; boundary tests.

### Slice 3 — The desktop shell

`Hooks::open_bundle`, the gate route, the marker flag, the startup and tick cleanup wiring; selftest runs never open a real file. `docs/desktop.md` lists the request.

Tests: gate tests for cookie, Host, Origin, method and non-empty body; the hook receives exactly the path the operation returned; open failure removes the file and is reported; the hidden-window boot test still passes.

### Slice 4 — The interface

`frontend/src/components/ConnectClaudeDesktop.tsx` (dialog), `lib/desktop.ts` (`connectClaudeDesktop`, `canConnectClaude`), `hooks/useAgents.ts` (status query), `lib/agentCopy.ts` (all new text), `pages/SettingsAgents.tsx` (the two actions, the "not available yet" list, the older-version mark), `lib/api.ts` and `lib/types.ts`. Fix the `ConnectInfo` test double that returns arguments the backend never sends.

Tests: each readiness state renders its sentence and offers the right control; confirm calls the shell request once and shows the outcome; no hand-off control outside the shell; the skill link points at the archive route; the older-version mark; no mutation handler invalidates queries.

### Slice 5 — Documentation and evidence

`docs/mcp.md` (Claude Desktop routes, the skill zip, the "not available yet" list), `docs/agents.md` (replace the "has not been connected" note with the two routes, removal of each, moving the app), `docs/desktop.md`, `docs/operations.md`, `CLAUDE.md` crate map (`musaic-commands`, `musaic-app`, `musaic-desktop`), `SECURITY.md` (the one hand-off), `CHANGELOG.md`, and `specs/007-claude-desktop-bundle/evidence/compatibility.md` with every real-host cell marked untested until the owner records it.

## Real-host evidence (the owner's to record)

Automated tests cannot install into Claude Desktop, and development never touches a real Claude configuration. The evidence table lists, per platform: whether opening the file reaches the install dialog; whether the installed-program shape starts the server; the wording shown for an unsigned bundle; what opening a newer bundle does; where the extension is removed; whether an extension and a configuration entry coexist; a read call; the ambiguous-album run; Cowork. Windows cells stay untested unless a Windows machine is used. A hand-made bundle of the installed-program shape is prepared for the first macOS observation before the implementation is finished, so the shape constant can be set from evidence.
